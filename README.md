# تطبيق مدرسة كوثر الأهلية — نسخة البداية

هذه نسخة أولية قابلة للتطوير، بتصميم عربي RTL وألوان أخضر بترولي وأبيض وبطاقات باستيل.

## الموجود حاليًا
- واجهة تسجيل دخول شكلية، ووضع معاينة.
- إدارة طلاب محلية.
- إدخال درجات وحساب متوسط عام.
- تسجيل حضور وغياب.
- إضافة إعلانات محلية.
- تخزين محلي في `localStorage`.
- ملف PWA مبدئي وService Worker للتخزين المؤقت.
- إعدادات Capacitor مبدئية لتجهيز Android.

## مهم جدًا
هذه النسخة **ليست نظامًا مدرسيًا جاهزًا للإنتاج**:
- تسجيل الدخول الحقيقي غير مفعّل.
- لا توجد مزامنة سحابية بين الأجهزة بعد.
- البيانات الحالية محفوظة على الجهاز/المتصفح نفسه فقط.
- لا تستخدم بيانات طلاب حقيقية قبل تنفيذ المصادقة والصلاحيات وقواعد قاعدة البيانات واختبار النسخ الاحتياطي.
- Service Worker يخزن ملفات الواجهة، ولا يعني أن كل الوظائف أو مزامنة البيانات تعمل دون اتصال.

## تشغيل نسخة الويب
1. ثبّت Node.js LTS.
2. افتح الطرفية داخل مجلد المشروع.
3. نفّذ:
   `npm install`
   `npm run dev`
4. افتح الرابط المحلي الذي يظهر في الطرفية.

## البناء للإنتاج
`npm run build`

## تجهيز Android (يتطلب Android Studio وAndroid SDK)
1. `npm install`
2. `npm run build`
3. `npx cap add android`
4. `npx cap sync android`
5. `npx cap open android`
ثم من Android Studio نفّذ Build APK.

## ربط Supabase لاحقًا
- أنشئ مشروعًا في Supabase.
- أنشئ جداول students, grades, attendance, announcements.
- فعّل Supabase Auth، والأفضل اعتماد OTP للهاتف أو آلية تحقق آمنة.
- أضف سياسات RLS دقيقة حسب دور المستخدم (مدير/معلم/طالب).
- لا تضع `service_role` key في الواجهة مطلقًا.
- تنفيذ outbox للمزامنة دون اتصال، ومعالجة التعارضات، واختبارات الصلاحيات مطلوب قبل الإطلاق.


## إعداد Supabase (الخطوة التالية)
1. أنشئ مشروعًا جديدًا من https://supabase.com/.
2. من SQL Editor نفّذ محتوى `supabase/schema.sql`.
3. من Project Settings > API انسخ Project URL والمفتاح العام (anon/publishable) إلى `www/supabase-config.js`.
4. فعّل Phone provider في Authentication، واضبط طريقة التحقق وسياسة كلمات المرور وفق متطلبات Supabase الحالية.
5. أنشئ المستخدمين عبر تدفق إداري موثوق، ثم أضف صفًا في `profiles` لكل `auth.users` مع الدور الصحيح (`admin` أو `teacher` أو `student`) و`active=true`.
6. لا تمنح المستخدمين صلاحية تغيير الدور أو حالة التفعيل. اختبر RLS بحسابات منفصلة قبل بيانات حقيقية.

## حالة التكامل الحالية
- شاشة تسجيل الدخول أصبحت تحاول المصادقة عبر Supabase عند وضع بيانات المشروع.
- مزامنة الطلاب/الدرجات/الحضور والإعلانات بين الأجهزة لم تُستكمل في هذه النسخة.
- المزامنة دون اتصال تحتاج إلى outbox محلي ومعرّفات ثابتة وسياسة لحل التعارضات؛ لا تعتبرها جاهزة.
- مكتبة Supabase JS تُحمّل من CDN؛ أول تحميل يتطلب الإنترنت. لتحسين العمل دون اتصال، ضمّن المكتبة محليًا في بناء الإنتاج.
